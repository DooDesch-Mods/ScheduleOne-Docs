Pack format reference

Look up the manifest.json fields of an NPC pack. A pack is this folder:

Needs Personnel 2.0+ for autoRegister, spawn, schedule and economy roles. Needs Personnel 2.3+ (schemaVersion 3) for supplier, portrait and lines.

manifest.json

Section titled “manifest.json”

Every field is optional. A minimal NPC only needs a name. Colours are #RRGGBB or #RRGGBBAA hex strings. Personnel logs a warning for an unknown value and skips it. A broken field never removes the whole NPC.

Ids and saves

Section titled “Ids and saves”
  • Personnel uses an authored id as given, normalized to lowercase a-z0-9_.
  • Without id, Personnel derives normalize(packId or folder name)_normalize(npc name).
  • packId (top level) fixes the derivation prefix. Renaming the pack folder then keeps the ids.
  • Ids must be unique inside a pack. The startup log prints the ids of each pack.
  • The id is the save identity. Never change it after you ship the pack.
  • To rename, set saveId to the OLD id. Existing saves then keep matching.

Auto-registration

Section titled “Auto-registration”

Set "autoRegister": true at top level, or "auto": true inside one NPC’s spawn. Personnel then registers the NPC as a real S1API world NPC. It is networked, saved and follows its schedule.

  • Everyone in a co-op session needs the same packs.
  • If a mod ships a compiled class for the same NPC id, the compiled one wins. The log says so.
  • The setting EnableAutoRegister turns auto-registration off globally.

spawn

Section titled “spawn”
KeyMeaning
x, y, zSpawn position.
rotationYSpawn yaw in degrees.
regionNorthtown, Westville, Downtown, Docks, Suburbia or Uptown.
physicaltrue: real world body that moves, collides and runs its schedule. false: phone contact only, almost no cost. Default: true exactly when the NPC has a schedule.
autoOverrides the pack’s autoRegister for this NPC.

Keep most NPCs of a large pack non-physical. For many physical NPCs, Siesta lowers the AI cost.

schedule

Section titled “schedule”

An array of actions. type decides the other fields. Times are "HH:MM" strings, durations are in-game minutes, positions are [x, y, z].

typeFields
walkTotime, position, faceDestination, within, warpIfSkipped
stayInBuildingtime, duration, building (name), doorIndex
sittime, duration, seatSet (name) or seatSetPath, includeInactive, warpIfSkipped
useVendingMachinetime, machineGuid (optional, nearest otherwise)
useAtmtime, atmGuid (optional)
useSlotMachinetime, position, bet, mode (single, spinCount, untilTime, untilBroke, untilTimeOrBroke), spins, endTime, timeBetweenSpins. Experimental in multiplayer.
locationDialoguetime, position, greetingOverride, choice, plus the walkTo fields
locationActiontime, position, duration, action (smokeBreak, graffiti, drinking, holdItem), equippablePath, graffitiRegion
driveToCarParktime, parkingLot (name), vehicle (name) or createVehicle: { "code": "shitbox", "position": [x,y,z], "rotationY": 0 }
dealSignalNo fields. Lets a dealer break its schedule for deals.
  • An unknown building or seat name logs a warning. The NPC skips that step.
  • warpIfSkipped: true places the NPC at the destination when no player was nearby and the step was skipped. Without it the NPC misses the stop and the log says nothing.
  • NPCs move only on the navmesh. An unreachable destination leaves the NPC where it was.
  • y need not be exact. The game samples the navmesh within about 5 units of the destination.

Console commands for coordinates

Section titled “Console commands for coordinates”

Needs Personnel 2.1+. Enable “Console enabled” in Settings and press the backtick key. Each result goes to your clipboard and to MelonLoader/Latest.log.

CommandResult
personnel pos[x, y, z] for any position field
personnel pos 07:30A finished walkTo action for that time
personnel spawnA spawn block with x, y, z, rotationY and region filled in
personnel route 07:30Appends a walkTo step to UserData/Personnel/route.json
personnel route showPrints the collected steps, ready to paste into "schedule": [ ... ]
personnel route clearStarts a new route
personnel npcs [filter]Loaded definitions, and where the physical ones are now

Vanilla teleport <property|npc id> moves you fast, for example teleport rv or teleport jessi_waters.

Without Personnel 2.1: run save in the console, then read Position from %USERPROFILE%\AppData\LocalLow\TVGS\Schedule I\Saves\<SteamID>\SaveGame_1\Players\Player_0\Player.json.

Roles: customer, dealer and supplier

Section titled “Roles: customer, dealer and supplier”

A customer, dealer or supplier block gives the NPC that economy role. If more than one exists, dealer wins, then supplier, then customer. Personnel applies only the fields you set. The rest keep the game defaults.

  • customer: spending, ordersPerWeek, preferredOrderDay (Monday to Sunday), orderTime, standards (VeryLow, Low, Moderate, High, VeryHigh), allowDirectApproach, guaranteeFirstSample, mutualRelationRequirement, callPoliceChance, dependence, affinities, preferredProperties.
  • affinities maps a drug type to a value from -1 to 1. Types: marijuana, methamphetamine, cocaine, mdma, shrooms, heroin.
  • preferredProperties takes property ids such as energizing.
  • dealer: type (player or cartel), cut, signingFee, home (building name), completedDealsVariable, allowInsufficientQuality, allowExcessQuality.
  • supplier: items (item ids such as ogkushseed or cocaleaf), minOrderLimit, maxOrderLimit, recommendMessage (text of the customer who recommends the supplier), unlockHint (text on the locked contact), stashDeadDrop (GUID of a vanilla dead drop for the cash stash; empty puts a stash next to the spawn).

A supplier works like the vanilla ones: the player orders by phone, the goods wait at a dead drop, and the debt is paid into the stash. The price of an item is its game price. The debt limit grows from minOrderLimit to maxOrderLimit with the relationship. A supplier always stands in the world, so spawn.physical: false is ignored.

portrait

Section titled “portrait”

"portrait": "portrait.png" sets the picture of the phone contact. Use a square PNG in the pack folder. Without it the game takes a picture of the NPC.

lines

Section titled “lines”

Own texts of the NPC. Every list holds variants; the game picks one at random. A text you leave out keeps the vanilla text of the NPC’s role.

  • greeting: what the NPC says when you talk to it, at any time of day.
  • phone: texts by key. A variant is one message, or a list of messages sent in a row.
  • reactions: short world reactions by key: annoyed, hurt, panic_start, noticed_pickpocket.

Phone keys and their placeholders:

RoleKeys
Customercontract_request, contract_accepted, contract_rejected, offer_expired, counteroffer_accepted, counteroffer_rejected (<PRODUCT>, <PRICE>, <QUALITY>, <LOCATION>, <WINDOW_START>, <WINDOW_END>); awaiting_deal, late_deal, deal_completed, customer_rejected_deal, offer_reject, post_deal_recommend (<NAME>), sample_sufficient, sample_insufficient
Dealerdealer_rob_defended, dealer_rob_partially_defended, dealer_rob_loss, inventory_depleted
Supplierdeaddrop_requested (<TIME>), deaddrop_ready (<LOCATION>), supplier_request_repayment (<DEBT>), supplier_unlocked, supplier_meet_confirm (<LOCATION>)

Any other vanilla key goes to the generic module. "Module/key" (for example "Generic/first_contract_request") picks the module by name.

contact and relationships

Section titled “contact and relationships”
  • contact.mapMarker: false removes the phone-map marker.
  • contact.visible: false skips the contact unlock, so the NPC shows as ”???”. Experimental.
  • relationships.delta is 0 to 5.
  • relationships.unlocked is a boolean.
  • relationships.unlockType is Recommendation or DirectApproach.
  • relationships.connections lists NPC ids. Use pack-prefixed ids for pack NPCs and plain ids such as jessi_waters for vanilla NPCs.

Layers

Section titled “Layers”

Each entry in faceLayers, bodyLayers and accessories uses one source:

KeyMeaning
pathA Resources path of an in-game layer or accessory. Personify stores these.
fileA PNG in the pack folder. Personnel registers it as a custom layer at load. See Custom PNG layers.
tint (alias color)Hex tint. Default white.

A file in faceLayers registers on the face mesh. A file in bodyLayers registers on the body mesh. Accessories take only path. Custom accessory meshes are not supported.

extensions

Section titled “extensions”

Free-form blocks keyed by consumer name, for example "backrooms": { ... }. Personnel passes them through untouched. Each consumer reads its own block.

Publish a pack

Section titled “Publish a pack”
  1. Export the pack from Personify. It wraps the pack for Thunderstore with manifest.json, README and LICENSE, and your pack under Personnel/Packs/<name>/.
  2. Add a 256x256 icon.png.
  3. List DooDesch-Personnel as a dependency and upload.
