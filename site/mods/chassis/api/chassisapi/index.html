ChassisApi

Namespace Chassis.Api

Public entry point for other mods: read and change the seat profiles Chassis uses per vehicle code.

Precedence, last one wins: a profile a mod registers with Register, the JSON file in UserData/Chassis/<code>.json. The file wins so a player or the debug console can always correct a mod’s values. Changes take effect on the next seat change; Changed tells seated rigs to re-read now.

Fields

Section titled “Fields”

ResolveUnknownOwner

Section titled “ResolveUnknownOwner”

Type: OwnerRecord

Host: asked once for a player-owned vehicle that has no record yet, for example one bought before Chassis kept owners. Return the owner and lock state to import, or null to let the vehicle belong to the host.

Properties

Section titled “Properties”

LocalDriverThrottle

Section titled “LocalDriverThrottle”

Added in 1.3.0

The local driver’s own throttle this physics step, before mods add to it in their own UpdateThrottle postfix. Chassis records it first; a pusher mod adds the pusher’s input after that, so a seated body’s hands follow only the driver’s keys.

LocalPlayerCode

Section titled “LocalPlayerCode”

The local player’s code, empty before the player exists.

FirstPersonActive

Section titled “FirstPersonActive”

The local player looks through the eyes of their seated body (key V).

FirstPersonKey

Section titled “FirstPersonKey”

The key that switches the first-person view, for a mod’s own key hints.

Folder

Section titled “Folder”

Folder of the JSON profiles.

Codes

Section titled “Codes”

Every vehicle code that has a profile.

GaugeSources

Section titled “GaugeSources”

Added in 1.2.0

Every gauge source by name: the built-in ones and those mods registered. A gauge, a switch’s ControlProfile.Source and VehicleTelemetry.Get read them.

Value Built in, with their units: “speed” (km/h or mph by the player’s setting), “speed_kmh”, “speed_mph”, “speed_raw” (vanilla’s signed km/h without the display factor), “rpm” (800 idle to 6000), “throttle” (-1 to 1), “handbrake”, “brake”, “reverse”, “lights”, “hazard” (each 0 or 1), “indicator” (-1, 0, 1), “indicator_left” and “indicator_right” (1 in the lit half of the flash), “steer” (-1 to 1), “steer_deg” (front wheel degrees), “clock” (HHMM), “clock_hours” (0 to 12), “clock_minutes” (0 to 60), “odometer” and “trip” (km or miles by the player’s setting), “odometer_km”, “trip_km”, “occupied” and “driver” (0 or 1).

UsesMph

Section titled “UsesMph”

Added in 1.2.0

True when the player set speeds and distances to miles (preference SpeedUnit = mph).

Events

Section titled “Events”

IndicatorChanged

Section titled “IndicatorChanged”

Raised on every peer with the vehicle and the new side when an indicator changes: -1 left, 1 right, 0 off, 2 hazard lights.

OwnersChanged

Section titled “OwnersChanged”

Raised on every peer after the host’s owner and lock records arrived and something changed.

FirstPersonChanged

Section titled “FirstPersonChanged”

Raised on this peer with the new state whenever the local first-person view turns on or off.

TuningChanged

Section titled “TuningChanged”

Added in 1.3.0

Raised on every peer with the car and the key after its tuning changed (”*”: everything at once).

Changed

Section titled “Changed”

Raised with the vehicle code after a profile was registered, loaded or edited.

ControlUsed

Section titled “ControlUsed”

Type: ControlUse

Added in 1.2.0

Raised on every peer after any switch was used, built-in actions included.

HeadlightsChanged

Section titled “HeadlightsChanged”

Added in 1.2.0

Raised on every peer when a vehicle’s headlights go on (true) or off (false).

BrakeChanged

Section titled “BrakeChanged”

Added in 1.2.0

Raised on every peer when a vehicle’s brakes go on (true) or off (false).

ReverseChanged

Section titled “ReverseChanged”

Added in 1.2.0

Raised on every peer when a vehicle starts (true) or stops (false) driving backwards.

DriverChanged

Section titled “DriverChanged”

Added in 1.2.0

Raised on every peer when someone takes the wheel (true) or the driver’s seat empties (false); players and NPCs.

Methods

Section titled “Methods”

PoseAsPusher

Section titled “PoseAsPusher”

Added in 1.3.0

Poses a player’s body behind a vehicle with the hands on the handles from ChassisProfile.Push. For the local player the key hints switch to the pusher’s keys. Returns false with the reason logged when the vehicle has no push profile or the body cannot be posed.

Parameter
glidetrue eases the body into the pose over a moment, false puts it there at once.

ReleasePusher

Section titled “ReleasePusher”

Added in 1.3.0

Lets go: the body of a player posed with PoseAsPusher moves on its own again.

PushedBy

Section titled “PushedBy”

Added in 1.3.0

The vehicle a player is posed behind, or null.

AddKeyHint(string, string, Func<KeyHintContext, bool>, params KeyCode[])

Section titled “AddKeyHint(string, string, Func<KeyHintContext, bool>, params KeyCode[])”

Types: KeyHintContext

Added in 1.1.0

Adds a line to the key hints at the bottom left while the local player sits in or pushes a vehicle, below First Person and Horn and above Indicators. show runs every frame and picks the vehicles and seats the key works in; null shows it in every vehicle. The same id again replaces the entry. Letters follow the keyboard layout, so KeyCode.Y shows the key labelled Y.

Parameter
idYour own unique id, e.g. “mymod.siren”.
labelThe text next to the key, e.g. “Siren”.
showWhether the line shows for the vehicle and seat in KeyHintContext; null shows it always.
keysOne key or several shown side by side, e.g. KeyCode.LeftArrow, KeyCode.RightArrow.

AddKeyHint(string, string, Func<KeyHintContext, bool>, Func)

Section titled “AddKeyHint(string, string, Func<KeyHintContext, bool>, Func)”

Types: KeyHintContext

Added in 1.1.0

Adds a key hint whose key can change while the game runs, for a key from a mod’s preferences. The key is read every frame and the hint follows it.

Parameter
idYour own unique id, e.g. “mymod.siren”.
labelThe text next to the key, e.g. “Siren”.
showWhether the line shows for the vehicle and seat in KeyHintContext; null shows it always.
keyRead every frame, e.g. () => myKeyEntry.Value for a MelonPreferences entry.

RemoveKeyHint

Section titled “RemoveKeyHint”

Added in 1.1.0

Removes a key hint a mod added; false when there was none with that id.

Assign

Section titled “Assign”

Gives one vehicle the profile of another code. For mods that build their vehicle on a vanilla one (a “veeper” under a camper van): without this, the profile would follow the vanilla code to every vehicle of that kind. Call it on every peer; it holds until Unassign or until the vehicle is gone.

Parameter
codeThe profile code to use, e.g. “mymod_camper”; it may be registered before or after this call.

Unassign

Section titled “Unassign”

Ends an Assign: the vehicle uses the profile of its own vehicle code again.

CodeOf

Section titled “CodeOf”

The profile code a vehicle uses: the assigned one, else its vehicle code.

For

Section titled “For”

Types: ChassisProfile

The profile a vehicle uses, or null when Chassis leaves it to vanilla.

RegisterSound

Section titled “RegisterSound”

Makes a clip available to profiles by name (HornProfile.Clip, HornProfile.Chirp).

Parameter
nameThe name profiles use, e.g. “mymod_horn”. The same name again replaces the clip. “chassis.click” (a cabin switch moves), “chassis.tick” and “chassis.tock” (the indicator relay) replace the built-in cabin sounds.

Honk

Section titled “Honk”

Sounds the horn of a vehicle on every peer, and with flash blinks its headlights twice. The host allows it when the local player sits in the vehicle or owns it. Every vehicle has a horn; the key is G.

Parameter
flashtrue also blinks the headlights twice.

HornClip

Section titled “HornClip”

Added in 1.8.0

The clip the horn of a vehicle plays: the tuned horn (“horn” tuning key) if one is set, else the profile’s HornProfile.Clip, else the built-in two-tone horn. Plays nothing; a shop uses it to let the player hear a horn on this machine only.

Parameter
stocktrue skips the tuned horn: the horn the vehicle has without parts.

SetIndicator

Section titled “SetIndicator”

Switches the indicator of a vehicle for every peer: -1 left, 1 right, 0 off, 2 hazard lights. The keys are the left and right arrows.

Parameter
side-1 left, 1 right, 0 off, 2 both sides (hazard lights).

Indicator

Section titled “Indicator”

The side a vehicle signals: -1 left, 1 right, 0 off, 2 hazard lights.

IndicatorLit

Section titled “IndicatorLit”

Whether the indicator of a vehicle is in the lit half of its flash right now; for mods that draw their own lamps.

SetPart

Section titled “SetPart”

Opens or closes a lid from the profile for every peer.

Parameter
partA PartProfile.Name from the vehicle’s profile, e.g. “boot”; case is ignored.
opentrue opens the lid, false closes it.

PartOpen

Section titled “PartOpen”

Whether a lid is held open by SetPart.

SetStorageEnd

Section titled “SetStorageEnd”

Tells every peer which end the vehicle’s storage is opened from, for lids with PartProfile.Storage. Vanilla storage counts as “rear” until a mod says otherwise.

Parameter
fronttrue for storage opened at the front, false for the rear.

OwnerOf

Section titled “OwnerOf”

Player code of the owner, or empty when the vehicle has no record (not player owned, or not synced yet).

IsMine

Section titled “IsMine”

True when the local player owns the vehicle.

IsLocked

Section titled “IsLocked”

True when the vehicle is locked; false when it has no owner record.

SetLocked

Section titled “SetLocked”

Locks or unlocks a vehicle the local player owns. A locked vehicle lets in its owner, and others only while the owner sits inside. There is no key for it: locking is up to mods (Yesla’s app) and this call.

SetOwner

Section titled “SetOwner”

Host only: gives a vehicle a new owner. Returns false on a client or for a vehicle that is not player owned.

Parameter
playerCodeThe new owner’s Player.PlayerCode, the same kind of value as LocalPlayerCode.

FitSeat(LandVehicle, int, Transform, Transform, float)

Section titled “FitSeat(LandVehicle, int, Transform, Transform, float)”

Types: SeatProfile

A first seat profile for one of a vehicle’s vanilla seats: the body sits on the seat, faces the vehicle’s front, holds the steering wheel (or rests the hands on the lap without one) and puts the feet into the footwell. A starting point for a new vehicle; fine-tune it with chassis profile set and save it.

Parameter
vehicleVehicle whose Seats entry the profile is for.
seatIndexIndex into LandVehicle.Seats.
frameModel frame the profile’s points are in (the transform at ChassisProfile.Frame).
steeringPivotSteering wheel pivot for “wheel” hands, or null for hands on the lap.
hipHeightHips above the vanilla seat transform, in metres.

FitSeat(LandVehicle, int, Vector3, Transform, Transform, float)

Section titled “FitSeat(LandVehicle, int, Vector3, Transform, Transform, float)”

Types: SeatProfile

As FitSeat, for a body that sits somewhere else than the vanilla seat: a mod’s own chair on a vehicle it built over a vanilla one.

Parameter
seatPointWorld point the hips rest on, minus hipHeight.

RegisterTuningPart

Section titled “RegisterTuningPart”

Types: TuningPart

Added in 1.3.0

Adds or replaces a tuning part. Register the same parts on every peer; cars that carry it rebuild.

RemoveTuningPart

Section titled “RemoveTuningPart”

Added in 1.3.0

Removes a tuning part; cars that carry it show the stock part until it is registered again.

TuningPartById

Section titled “TuningPartById”

Types: TuningPart

Added in 1.3.0

The registered part with this id, or null.

TuningParts

Section titled “TuningParts”

Types: TuningPart

Added in 1.3.0

The registered parts that fit this car, optionally only one slot.

InstallPart

Section titled “InstallPart”

Added in 1.3.0

Installs a part into its slot, replacing what was there.

RemovePart

Section titled “RemovePart”

Added in 1.3.0

Takes the part out of a slot; the car shows the stock part again.

InstalledPart

Section titled “InstalledPart”

Added in 1.3.0

The part id in a slot, or null for stock.

SetPaint

Section titled “SetPaint”

Types: TuningFinish

Added in 1.3.0

Paints the body, or with secondary the second paint (secondary paint targets and “paint2” parts), in any colour with a finish from TuningFinish.

SetPaintTargets(LandVehicle, IEnumerable)

Section titled “SetPaintTargets(LandVehicle, IEnumerable)”

Types: PaintTarget

Added in 1.7.0

Names the material slots that take this car’s body paint, for a car whose visible body is not its VehicleColor.BodyMeshes (a model of your own on a stock car). Set it on every peer. Null goes back to the body meshes. A paint already on the car moves to the new slots.

SetPaintTargets(string, Func<LandVehicle, IEnumerable>)

Section titled “SetPaintTargets(string, Func<LandVehicle, IEnumerable>)”

Types: PaintTarget

Added in 1.7.0

The same for every car of a vehicle code; a target set on the car itself comes first. Null removes it.

PaintTargetsOf

Section titled “PaintTargetsOf”

Types: PaintTarget

Added in 1.7.0

The material slots the car’s body paint goes on now.

HasOwnPaintTargets

Section titled “HasOwnPaintTargets”

Added in 1.7.0

True when a mod named this car’s paint targets. The game’s own colours (LandVehicle.ApplyColor) still paint the vanilla body, so a shop offers only custom paint for such a car.

HasSecondPaint

Section titled “HasSecondPaint”

Added in 1.7.0

True when the car has PaintTarget.Secondary targets, so the second paint shows on its body.

PaintRenderers

Section titled “PaintRenderers”

Types: PaintTarget

Added in 1.7.0

Paints material slots that belong to no tuned car, on this machine only: e.g. a model that stays when the car it rides on is gone. paint is a “paint” value (RRGGBB,finish); null or empty puts the original materials back. The mod saves and syncs the value itself.

ClearPaint

Section titled “ClearPaint”

Added in 1.3.0

Back to the vanilla paint.

SetRimColor

Section titled “SetRimColor”

Types: TuningFinish

Added in 1.3.0

Rim colour; null for the stock rim colour.

SetXenon

Section titled “SetXenon”

Added in 1.3.0

Headlight colour; null for the stock headlights.

SetNeon

Section titled “SetNeon”

Added in 1.3.0

Underglow in a colour on the given sides (“fblr”: front, back, left, right); null switches it off.

SetWindowTint

Section titled “SetWindowTint”

Added in 1.3.0

Window glass colour with its alpha as the darkness; null for the profile’s tint. Needs the base interior.

SetTyreSmoke

Section titled “SetTyreSmoke”

Added in 1.3.0

Drift smoke colour; null for the stock white. The smoke shows on the driver’s screen, as in vanilla.

SetHorn

Section titled “SetHorn”

Added in 1.3.0

Horn sound from RegisterSound; null or empty for the profile’s horn.

SetTuning

Section titled “SetTuning”

Added in 1.3.0

Sets any tuning key; an empty value removes it.

GetTuning

Section titled “GetTuning”

Added in 1.3.0

The value of one tuning key, or null.

Tuning

Section titled “Tuning”

Added in 1.3.0

A copy of every tuning key of a car.

PreviewTuning

Section titled “PreviewTuning”

Added in 1.7.0

Shows a tuning key on this machine only. Same keys and values as SetTuning; an empty value shows the key removed, key ”*” with an empty value shows the whole car stock.

PreviewPart

Section titled “PreviewPart”

Added in 1.7.0

Shows a part in its slot on this machine only.

EndPreview

Section titled “EndPreview”

Added in 1.7.0

Ends the preview of one key, or every preview on the car when key is null.

IsPreviewing

Section titled “IsPreviewing”

Added in 1.7.0

Whether the car shows a preview on this machine.

ShownTuning

Section titled “ShownTuning”

Added in 1.7.0

The value the car shows on this machine: the preview where there is one, else the real tuning.

TuningStatsOf

Section titled “TuningStatsOf”

Types: TuningStats

Added in 1.3.0

The driving factors of all parts on the car together.

ClearTuning

Section titled “ClearTuning”

Added in 1.3.0

Puts the whole car back to stock.

Get

Section titled “Get”

Types: ChassisProfile

The profile for a vehicle code, or null when Chassis leaves that vehicle to vanilla.

Parameter
vehicleCodeA code like “shitbox”; see ChassisProfile.Code for the list.

Register

Section titled “Register”

Types: ChassisProfile

Adds or replaces a profile from code. A JSON file for the same code still wins; returns false when one does.

Parameter
profileThe profile; its ChassisProfile.Code must be set.

Save

Section titled “Save”

Writes the current profile of a vehicle code to its JSON file; from then on the file wins.

Returns The full path of the written file, UserData/Chassis/<code>.json.

NotifyChanged

Section titled “NotifyChanged”

Tells seated rigs that a profile changed in place, so they re-read it this frame.

Reload

Section titled “Reload”

Drops every loaded profile and reads the profiles mods registered and the files again.

SetInterior

Section titled “SetInterior”

Types: ChassisProfile

Added in 1.2.0

Builds a mod’s own interior into every vehicle that uses the profile code, in place of the base interior’s seats, dashboard and wheel. The lining and the tinted glass of InteriorProfile stay; set InteriorProfile.Lining to false or InteriorProfile.Glass to null in configure to drop them. Call it on every peer; the same code again replaces the factory and rebuilds the vehicles that have one.

Parameter
codeThe profile code, e.g. “shitbox” or a mod’s own code from Assign.
buildMakes the interior for one vehicle. Chassis parents the object to the vehicle’s frame and keeps its local position, rotation and scale, so place it in the frame’s space (x right, y up, z forward, metres).
configureChanges the profile to match the new interior: ChassisProfile.Steering, ChassisProfile.Gauges, ChassisProfile.Controls, the driver’s hands. It runs once on every profile object of this code: the one there now, the one Chassis fits for a vanilla car the first time one is seen, and one from a JSON file. Null leaves the profile as it is.

RemoveInterior

Section titled “RemoveInterior”

Added in 1.2.0

Ends SetInterior: the vehicles of this code get the base interior again. False when there was none.

Changes a configure callback made to the profile stay until the profile is reloaded (Reload).

RegisterGaugeSource

Section titled “RegisterGaugeSource”

Added in 1.2.0

Adds a gauge source of a mod’s own: a fuel level, a battery, a siren state. read runs for every gauge that shows it, every frame, on every peer; keep it cheap and return the same value on every peer. NaN or an exception reads as not valid. The same name again replaces the source; a built-in name throws.

Parameter
nameYour own unique name, e.g. “mymod.fuel”.
readThe value for one vehicle, in a unit of your choice; gauges map it with Min and Max.

RegisterControlAction

Section titled “RegisterControlAction”

Types: ControlUse

Added in 1.2.0

Gives a switch action of a mod’s own a handler. Switches whose ControlProfile.Action has this name call it on every peer once the host passed the use on; do world changes only where ControlUse.IsHost is set. Chassis keeps and saves the state of toggles and knobs itself; read it with ControlValue. The same name again replaces the handler.

Parameter
actionYour own unique name, e.g. “mymod.siren”; built-in names throw.

UseControl

Section titled “UseControl”

Added in 1.2.0

Uses a switch as if the local player clicked it, without the reach check: a button fires, a toggle flips, a knob goes to value (or back to its default when that is null).

Parameter
controlA ControlProfile.Name from the vehicle’s profile.
valueKnob: the new value. Toggle: 0 or 1, or null to flip. Ignored for a button.

ControlValue

Section titled “ControlValue”

Added in 1.2.0

A switch’s state: 0 or 1 for a toggle, the knob’s value, 0 for a button.

A switch with a ControlProfile.Source reports that source’s value.

RegisterOccupantDown

Section titled “RegisterOccupantDown”

Types: OccupantDown

Added in 1.2.0

Decides what happens to an NPC that dies or is knocked out in its seat, for example from a gunshot through the window. Return true to keep the body slumped in the seat; the car then stops where it is. Return false for vanilla: the NPC falls out next to the car as a ragdoll. The NPC stays seated when any handler returns true. Runs on the host only; clients follow the host. A knocked-out NPC that wakes up in its seat sits up again.

Parameter
nameYour handler’s name, e.g. “mymod.gta-style”; registering the same name again replaces it.

RemoveOccupantDown

Section titled “RemoveOccupantDown”

Added in 1.2.0

Removes a handler added with RegisterOccupantDown; false when there was none by that name.
